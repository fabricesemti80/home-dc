# Domain docs

This repository uses a single-context layout: `GLOSSARY.md` at the root and decisions under `docs/adr/`.

## Before exploring

- Read `GLOSSARY.md` if present. If a future `GLOSSARY-MAP.md` exists, follow it to the glossaries relevant to the task.
- Read ADRs under `docs/adr/` that concern the area being changed.
- If these documents are absent, proceed silently. Create them lazily through the domain-modeling skill when terms or decisions are resolved.

## Using domain docs

Use the glossary's defined terms in issues, proposals, hypotheses, and tests. Reconsider invented synonyms; note genuine terminology gaps for domain-modeling.

If a proposal contradicts an ADR, identify the ADR and explain why the decision should be reconsidered.
